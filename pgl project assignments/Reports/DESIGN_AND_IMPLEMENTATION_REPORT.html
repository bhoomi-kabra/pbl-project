1. Executive Summary & Problem Statement

Urban infrastructure projects across the Nashik Municipal Corporation (NMC) frequently suffer from lack of contractor accountability. Under municipal guidelines, contractors are bound by a 24 to 36 Month Defect Liability Period (DLP), during which any road degradation must be repaired at the contractor's cost. However, citizens lack visibility into tender details, and contractors historically close citizen tickets without verifiable photographic audit proof.

Nashik Roads & Civic Monitor bridges this civic accountability gap through an end-to-end platform integrating:

  • Interactive GIS Infrastructure Mapping: Real-time mapping of road projects across Panchavati, Nashik East, Nashik West, Cidco, Satpur, and Nashik Road with project lifecycle stages (Trenching, Concreting, Curing, Completed).
  • "Closed != Resolved" Citizen Verification Audit: A 5-stage resolution workflow requiring side-by-side Before/After geotagged photo evidence and citizen sign-off before official closure.
  • Contractor Defect Liability Tracking: Public dashboard showing contractor names, budgets (₹ Cr), and DLP warranty countdowns.
  • Bilingual Accessibility & AI Assistance: 100% synchronized English & Marathi translation with AI hazard classification.

2. Architectural Evolution & Design Changes

The system evolved through five verifiable engineering iterations documented in the project repository:

Change 1: Desktop MVP to Mobile-First Real-Time Architecture (Commit: 03c47c2)

The initial proof-of-concept was restricted to a static desktop dashboard. It was refactored into a mobile-first responsive citizen portal with fixed bottom navigation (BottomMobileNav.tsx), a social grievance feed (SocialMediaFeed.tsx), and an Express REST API backend with persistent JSON disk storage.

Change 2: Enforcing "Closed != Resolved" Citizen Audit Workflow (Commit: d93aadc)

Unilateral contractor closures were eliminated. A dedicated verification engine (VerificationTracker.tsx) was introduced, requiring photographic before/after proof and reporter identity verification before any ticket can enter the VERIFIED & CLOSED state.

Change 3: UI/UX Standardization to Municipal High-Contrast Light Mode (Commit: 280b09c)

Initial dark-mode styling caused poor legibility during projector reviews and municipal report printing. The interface was standardized to a clean, crisp Light Mode adhering to WCAG AAA contrast guidelines, while keeping theme switching functional.

Change 4: Geotagging Precision via Landmark Coordinate Snapping (Commit: 60f45a3)

Complaints previously clustered at generic ward centroids. A landmark coordinate lookup table (LANDMARK_COORDINATES) and an interactive Leaflet draggable mini-map pinpoint picker were added, bringing location accuracy to within 5 meters.

Change 5: Client-Side WebP Compression Pipeline

High-resolution phone cameras produce 5+ MB images, exhausting server disk buffers. A client-side HTML5 Canvas downsampling pipeline was implemented, resizing images to max 1024px width at 75% WebP quality, reducing transfer payloads by 95.8% (under 250 KB).

3. Module-Wise Implementation Details

Module A: Interactive Leaflet GIS Engine (GisMap.tsx)

Built with Leaflet 1.9.4 and CartoDB Voyager tiles centered at [19.9975, 73.7898]. Renders color-coded road project layers and live citizen hazard pins. Includes React useEffect cleanup hooks (map.remove()) to prevent memory leaks and DOM re-initialization crashes.

Module B: Citizen Grievance Filing (ComplaintFormModal.tsx)

Hierarchical category selector (Pothole, Water Leakage, Open Manhole, Electrical Sparking, Garbage). Features fuzzy landmark auto-snapping, draggable pinpoint mini-map, 10-digit Indian phone regex validation (/^[6-9]\d{9}$/), and client-side photo compression.

Module C: "Closed != Resolved" Verification Audit (VerificationTracker.tsx)

Enforces a 5-stage progress milestone: SUBMITTED → ASSIGNED → IN_PROGRESS → PENDING_VERIFICATION → VERIFIED & CLOSED. Displays side-by-side Before Repair vs. After Repair evidence photos with citizen verification sign-off.

Module D: Contractor Defect Liability Period (DLP) Dashboard (AdminDashboard.tsx)

Municipal portal monitoring road tenders (e.g. NMC-TND-2026-084), contractor agencies (e.g. L&T Smart Infra Nashik), approved budgets (₹ Cr), and 24–36 month DLP warranty countdowns. Enables ward engineers to track SLA turnaround and issue penalty notices.

Module E: AI-Assisted Smart Grievance Chatbot (ChatbotWidget.tsx)

Conversational natural language assistant that classifies hazard intent (e.g., "Broken streetlight sparking on College Road" → ELECTRICAL_HAZARD at 98% confidence) and provides 1-click form pre-filling.

Module F: Bilingual Localization Engine (translations.ts)

Complete internationalization engine with 100% dictionary parity across English and Marathi (मराठी), covering municipal departments, hazard tags, rules, and helpline directories.

4. Database Schema & Data Models

The backend schema (server/schema.sql) defines five core relational entities compatible with PostgreSQL / Supabase PostGIS:

Table Name Primary Key Key Attributes Purpose
civic_tickets UUID / String ticket_number, hazard_type, ward, lat, lng, status, photo_before, photo_after Stores citizen grievances, GPS coords, and resolution evidence.
road_projects UUID / String tender_id, road_name, contractor, budget_inr, dlp_period, state, lat, lng Tracks municipal road tenders, contractor warranty, and progress stage.
contractors UUID / String agency_name, contact_phone, performance_score, active_projects Contractor directory and Defect Liability performance ratings.
ticket_audits UUID / String ticket_id, verified_by, verification_timestamp, citizen_feedback Enforces 'Closed != Resolved' citizen sign-off before ticket closure.
